# ADR-0004: MVPオークションの入札・終了・出品変更ルール

- 状態: 採用（MVPの業務ルール）
- 日付: 2026-10-30
- 備考: 当初 `docs/architecture/ADR-0003-auction-operating-rules.md` として追加。`adr/0003-production-stack-pending.md` と番号が重複していたため ADR-0004 に振り直し（内容は変更なし）
- 決定者: プロダクトオーナーの依頼に基づき仕様化
- 関連: [`auction-rules.md`](../../product/auction-rules.md)、[`auction-site-spec.md`](../../product/auction-site-spec.md)

## 背景

MVPの実装前に、最低入札増分、同額入札、終了直前の入札、公開済み出品の編集・取り下げ条件を一意に定める必要があった。曖昧なままでは入札競合や出品者による条件変更が利用者間の不公平につながる。

## 決定

### 最低入札増分

初回入札は開始価格以上とし、増分を加算しない。2件目以降は直前の最高入札額に次の増分を適用する。

| 直前の最高入札額 | 最低増分 |
|---:|---:|
| 1〜999円 | 10円 |
| 1,000〜4,999円 | 50円 |
| 5,000〜9,999円 | 100円 |
| 10,000〜49,999円 | 500円 |
| 50,000〜99,999円 | 1,000円 |
| 100,000円以上 | 2,000円 |

新しい入札額は最低額以上の任意の整数JPYとし、増分の倍数を要求しない。最低増分は出品者が個別変更できない。

本表をMVPルール版1とする。公開時にオークションへ適用版を固定し、開催中はルール版を切り替えない。

### 同額入札

有効な入札は、DB上でオークションの受付ロックを取得した順に直列化する。同額となる入札が競合した場合、先に受付確定した入札を優先する。先行入札の確定後、後続リクエストは最新価格に対する最低額で再検証するため、同額の後続入札は通常 `BID_TOO_LOW` として拒否される。最高入札者は金額が最高の受付済み入札者とし、同額が既存データにある場合は受付順が最も早い入札者とする。

### 終了直前の入札

オークションの終了時刻は延長しない。入札APIは対象オークションの直列化ロック取得後にDB基準時刻を読み、`受付時刻 < ends_at` の場合のみ受付ける。`受付時刻 == ends_at` またはそれ以降は拒否する。終了時刻の判定にブラウザ時計を使用しない。受付順・時刻・入札記録・最高価格更新は同一トランザクションで確定する。

### 出品の編集

- 下書きは出品者が全項目を編集できる。
- 公開後で受付済み入札がない場合、出品者は商品情報、画像、開始価格、時刻、配送条件を編集できる。最低増分は固定表を適用する。変更を再検証し、変更者・変更時刻を記録する。
- オークション開始前は開始時刻を現在時刻以降に変更できる。開催開始後は開始時刻を変更できない。いずれの場合も終了時刻は更新受付時刻より後でなければならない。
- 受付済み入札が1件以上ある場合、出品者は出品条件を変更できない。入札者に影響しない誤記訂正等は、運営者の審査と理由付き監査記録を経た場合のみ許可する。
- 運営停止・審査中は出品者による編集・再公開を許可しない。

### 出品の取り下げ・停止

- 下書きは出品者が破棄できる。
- 公開後でも受付済み入札がない場合、出品者は取り下げ可能。状態を `cancelled` にし、公開・入札受付から除外して操作を監査記録に残す。
- 受付済み入札が1件以上ある場合、出品者による取り下げ・キャンセルは禁止し、終了まで継続する。
- 運営者は規約違反、安全上の懸念、法的要請等に対し理由を記録して出品を停止できる。停止中は入札を拒否する。
- 運営停止を終了前に解除する場合は元の終了時刻を維持する。停止中に終了時刻を過ぎた場合は `cancelled` として終了し、落札者・注文を作成しない。
- 運営者が入札後のオークションをキャンセルしても入札履歴は保持し、注文は作らず、理由・操作者を監査記録に残す。

## 理由

- 価格帯別の増分は低価格商品の入札幅を抑えながら、高価格帯で過剰に細かい入札を減らせる。境界値が明確でテストしやすい。
- DBで受付を直列化することで、同時刻のリクエストをブラウザ到着時刻やネットワーク遅延で判定せずに済む。
- 自動延長を行わず、固定終了時刻と厳密な `< ends_at` 条件を使うことで、MVPの境界挙動を単純かつ検証可能にする。
- 入札後に出品者が条件を変更・撤回できないようにし、入札者の期待と履歴の整合性を守る。

## 影響・実装要件

- 増分表をドメインロジックとして一元化し、UIの最低額表示とサーバー検証で共有する。公開時にルール版を固定する。
- オークションごとのDBロックまたは同等の直列化を実装し、入札の冪等性キー、受付時刻、順序を記録する。
- 価格帯の各境界、初回入札、任意整数額、同時同額入札、終了時刻の直前・一致・直後、編集・取り下げの入札有無別権限を単体/統合テストする。
- 出品変更・取り下げ・運営停止/解除/キャンセルは監査記録を残す。終了・落札・注文作成と競合させる統合テストを行う。
- この決定はMVP内に限る。手数料、KYC、決済、入札取消、返品・紛争の判断は含まない。

## 見直し条件

公開前レビュー、入札データの異常な価格分布、運営・法務上の要請に基づき変更が必要な場合は、適用対象となる既存開催中オークションを含む移行方法を別ADRで決める。開催中の増分・終了時刻を遡及変更しない。
