# ADR-0007: オークションの仕様を Yahoo!オークションに合わせる

- 状態: 採用（方針）。MVP に入れる範囲は PR で全員確認
- 日付: 2026-11-06
- 決定者: hbsryuryu（チームでの確認は PR で行う）
- 置き換え: [ADR-0004](0004-auction-operating-rules.md) のうち「最低入札増分」「同額入札」「終了直前の入札」。ADR-0004 の「出品の編集」「出品の取り下げ・停止」は引き続き有効
- 関連: [`yahoo-auctions-alignment.md`](../../product/yahoo-auctions-alignment.md)（仕様の比較表）、[`auction-rules.md`](../../product/auction-rules.md)、[`auction-bid-transaction.md`](../designs/auction-bid-transaction.md)

## 背景

チームとして、国内の代表的な個人間オークションである Yahoo!オークションを参考サービス（ロールモデル）とし、オークションの仕様をそれに合わせる方針を決めた。
一方、ADR-0004 では MVP の入札ルールを独自に決めており（独自の増分表、自動延長なし、自動入札は対象外）、Yahoo!オークションとは異なっていた。

## 決定

### 1. 方針

- **オークションの仕様（入札・終了・出品のルール）は Yahoo!オークションに合わせる。**
- 合わせるのは**ルールと利用体験**であり、**商標・ロゴ・画面デザイン・文章・画像は使わない**（AGENTS.md の方針どおり）。サービス名は「めぐる市」のまま。
- Yahoo!オークションの仕様は変わることがあるため、参照した内容は確認日つきで [`yahoo-auctions-alignment.md`](../../product/yahoo-auctions-alignment.md) に記録し、実装前に再確認する。
- 公式ヘルプに書かれていない細部（同額の扱いなど）は、本プロジェクトで決めて明記する。

### 2. 入札単位（ADR-0004 の増分表を置き換え）

「現在の価格」に応じて、次の入札で上乗せする最低金額を決める（2026-11-06 確認）。

| 現在の価格 | 入札単位 |
|---:|---:|
| 1円〜1,000円未満 | 10円 |
| 1,000円〜5,000円未満 | 100円 |
| 5,000円〜1万円未満 | 250円 |
| 1万円〜5万円未満 | 500円 |
| 5万円以上 | 1,000円 |

- 最低入札額は、入札者がいない場合は「開始価格」、入札者がいる場合は「現在の価格＋入札単位」。
- 最低入札額以上なら、**1円単位**で入札額を決められる（入札単位の倍数でなくてよい）。

### 3. 自動入札（すべての入札を最高入札額として扱う）

- 入札者は、払ってもよい**最高入札額**を入力する。システムは、ほかの入札者と競るたびに、最高入札額の範囲で自動的に価格を上げる。
- **現在の価格**は、次のように決める。
  - 入札者が1人：開始価格
  - 入札者が2人以上：「2番目に高い最高入札額＋入札単位」。ただし1番目の最高入札額を超えない
- 例（入札単位10円の価格帯）：
  - Aさんが最高入札額700円 → Bさんが500円で入札すると、Aさんが最高額入札者のまま、現在の価格は510円
  - その後 Bさんが715円で入札すると、Bさんが最高額入札者になり、現在の価格は710円
- 最高入札額は、**本人以外には表示しない**。
- **同額の最高入札額**（公式ヘルプに記載がないため本プロジェクトで決定）：先に受付確定した入札者を最高額入札者とし、現在の価格はその最高入札額とする。
- 最高額入札者は、自分の最高入札額を**上げる**ことができる（現在の価格は変わらない）。下げる操作は MVP では提供しない。

### 4. 自動延長（ADR-0004 の「延長しない」を置き換え）

- 出品者が出品時に「自動延長：あり／なし」を選ぶ。**既定値は「あり」**とする（本プロジェクトで決定）。
- 「あり」の場合、**終了5分前から終了までの間に「現在の価格」が上がると、終了時刻を5分延長する**。延長後も同じ条件で何度でも延長する。
- 入札があっても現在の価格が上がらない場合（最高額入札者が自分の最高入札額を上げた場合など）は延長しない。
- 延長の判定と終了時刻の更新は、入札の受付と同じトランザクション内で行う。判定にはロック取得後の DB 時刻を使う（`受付時刻 < ends_at` の条件は変えない）。

### 5. 即決価格

- 出品者は任意で即決価格を設定できる（開始価格より高い金額）。
- 即決価格以上で入札すると、**その時点で即決価格で落札**し、オークションを終了する。この場合、自動入札は働かない。

### 6. 早期終了

- 出品者は、終了日時より前にオークションを終了できる。
- 入札者がいる場合は、その時点の最高額入札者が、その時点の現在の価格で落札する。入札者がいない場合は落札者なしで終了する。
- 早期終了は「取り下げ（キャンセル）」とは別の操作であり、ADR-0004 の「受付済み入札がある場合は取り下げできない」は変わらない。

### 7. 終了日時

- 出品者は、出品時刻から **13時間後〜7日11時間後** の範囲で、**1時間単位**で終了日時を選ぶ（Yahoo!オークションのアプリ出品の範囲に合わせる）。

### 8. MVP に入れないもの（将来検討・採用しない）

| 機能 | 扱い | 理由 |
|---|---|---|
| 入札者の制限（評価による制限、SMS 認証済みのみ等） | 将来検討 | 評価機能が前提のため |
| 自動再出品・自動値下げ | 将来検討 | MVP の主要フローに不要 |
| フリマ（定額）形式 | 将来検討 | 別の販売形式になるため |
| 入札予約 | 将来検討 | 予約実行のジョブが必要なため |
| 入札者の削除（出品者による入札の取り消し） | 将来検討 | 繰り上げ落札などのルール設計が必要なため |
| 有料オプション（注目のオークション等） | 採用しない | 決済・課金が前提のため |
| 最低落札価格 | 採用しない | Yahoo!オークション側で2019年に設定が終了しているため |

## 理由

- 参考サービスをはっきり決めることで、細かい仕様の判断をチーム内で迷わずにできる。利用者にも馴染みのある体験になる。
- 自動入札と自動延長は、終了間際の「一発入札」による不公平を減らす。参考サービスと同じ考え方を取る。

## 影響

- **MVP の範囲が広がる**：自動入札・自動延長・即決価格・早期終了が MVP に入る。AGENTS.md 2.1 / 2.2、`mvp-scope.md` を更新した。
- **データモデル**：`Bid` に本人以外には見せない最高入札額を持たせる。`Auction` に自動延長の有無、即決価格、延長後の終了時刻、早期終了の記録を持たせる。
- **入札処理**：[`auction-bid-transaction.md`](../designs/auction-bid-transaction.md) の最低額判定を、自動入札による価格計算に変えた。延長・即決も同じトランザクションで確定する。
- **テスト**：入札単位の各境界、自動入札の価格計算（勝ち・負け・同額）、終了5分前の境界（延長あり・なし）、連続延長、即決、早期終了と入札の競合を追加する。
- **静的デモ（`app.js`）**：まだ古いルールのまま。別の PR で合わせる。

## 見直す条件

- Yahoo!オークションの仕様が変わり、本 ADR の内容と食い違ったとき（追随するかをチームで判断する）
- MVP の実装量が大きくなりすぎたとき（一部を「将来検討」に戻す）
