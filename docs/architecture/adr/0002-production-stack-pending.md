# ADR-0002: 本番技術スタックと未決プロダクト事項を保留する

- 状態: 提案（採用判断待ち）
- 日付: 2026-10-10

## 背景

リポジトリには静的HTML/CSS/JavaScriptのプロトタイプのみがあり、サーバー、DB、認証、デプロイ先は存在しない。AGENTS.mdに列挙された技術は初期候補であって採用済みではない。また、決済・手数料、KYC、キャンセル、禁止商品、終了延長等の事業ルールは未決事項である。

## 提案

本ADRでは本番スタックを決定しない。静的プロトタイプはレビュー用途として維持し、本番の認証、API、DB、ストレージ、ジョブ、メール、監視サービスの導入前に選定ADRを作る。技術選定とプロダクト・法務判断を混同しない。

## 選定時の評価項目

- 運用するチームの経験と保守能力
- 入札のトランザクション、ロック、ユニーク制約を正しく実装できること
- 認証・セッション・メール確認を安全に運用できること
- 画像の安全なアップロード・配信と個人情報保護
- バックアップ、復旧、監視、コスト、リージョン
- ライセンス、保守状況、ベンダーロックイン、移行可能性
- stagingとproductionの分離、秘密情報管理

## 未決事項と責任者

| 判断 | 状態 | 決定前に必要な検討 |
|---|---|---|
| API / Web / DB技術 | 未決 | チーム能力、競合制御、運用費用 |
| 認証・メール事業者 | 未決 | メール確認、復旧、アカウント保護 |
| 画像保管・変換 | 未決 | 形式・サイズ検査、EXIF、アクセス制御 |
| クラウド・監視 | 未決 | 環境分離、ログ、アラート、バックアップ |
| 収益化・税 | 未決 | 事業モデルと専門家確認 |
| 決済・KYC・出金 | 未決 | 法令、本人確認、返金、紛争運用 |
| 禁止商品・年齢制限 | 未決 | 審査基準、通報、停止、異議申立て |
| 終了・同額入札 | 未決 | 利用者への公平な説明と競合仕様 |

各判断の事業責任者・運用責任者は未設定。担当者と期限を設定してから採用ADRを承認する。

## 影響

この保留中も静的プロトタイプのUI改善は可能だが、本番取引データを受け付けてはならない。API文書は将来案であり、実装契約として使用する前に採用スタックと仕様を決定する。

## 見直し条件

運用責任者、初期ユーザー規模、公開地域、決済を含む提供範囲、可用性目標が確認できた時点で、本ADRを置き換える選定ADRを作成する。
