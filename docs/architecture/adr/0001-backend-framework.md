# ADR-0001: バックエンドフレームワーク

- 状態: 提案中
- 日付: 2026-10-10
- 決定者: TBD（チームで決定）

## 背景

AGENTS.md 3章ではバックエンドの初期候補を「TypeScript + Node.js（モジュラーモノリス）」としている。
チームでは Hono を候補とし、FastAPI を拡張として使う可能性も検討している。

## 選択肢

1. **Hono（TypeScript）のみ**
   - 長所: AGENTS.md の方針と一致。フロント（Next.js）とドメイン型・バリデーション（Zod 等）を共有しやすい。軽量で学習しやすい。
   - 短所: Python のライブラリ（画像処理・データ分析等）は直接使えない。
2. **FastAPI（Python）のみ**
   - 長所: 型ヒントベースで OpenAPI を自動生成。Python のエコシステムが使える。
   - 短所: AGENTS.md の方針と言語が異なる。フロントとの型共有は OpenAPI 経由のコード生成が必要。
3. **Hono をメイン + FastAPI を拡張用の別サービス**
   - 長所: 主要な業務ロジックは TypeScript に集約しつつ、Python が得意な処理だけ切り出せる。
   - 短所: 2言語・2サービスの運用コスト。初期はモジュラーモノリス方針と衝突しやすい。
