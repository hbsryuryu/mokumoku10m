# AUTH-001: Google ログイン（要件）

- 機能ID: AUTH-001
- 状態: 提案中（チーム確認待ち）
- 作成日: 2026-10-30
- 関連: AGENTS.md 2.1 #1・7章、[`mvp-scope.md`](mvp-scope.md) #1、[ADR-0001](../architecture/adr/0001-backend-framework.md)、設計は [`auth-001-google-login-design.md`](../architecture/auth-001-google-login-design.md)

## 背景・決定

2026-10-30、ユーザー（hbsryuryu）の指示により **ログイン方式は Google 認証** とする。
会員登録・ログインを Google アカウントに任せることで、パスワード管理とメール確認を自前で持たずに済む。

## スコープ

| 含む | 含まない（MVP では扱わない） |
|---|---|
| Google アカウントでのログイン | メールアドレス＋パスワードでのログイン |
| 初回ログイン時のアカウント作成（＝会員登録） | Google 以外の外部ログイン（Apple、LINE、X など） |
| 初回のニックネーム（公開表示名）設定 | 1ユーザーへの複数ログイン手段の連携・統合 |
| ログアウト | Google Drive など他の Google API へのアクセス |
| ログイン状態（セッション）の維持・失効 | 二段階認証の自前実装（Google 側に任せる） |
| 未ログイン時の入札・出品・ウォッチでのログイン誘導 | |
| 利用停止ユーザーのログイン拒否 | |

## 利用者ストーリー

- ゲストとして、Google アカウントのボタン1つで会員登録・ログインしたい。新しいパスワードを覚えたくないから。
- 会員として、次回訪問時もログインしたままでいたい。毎回ログインするのは面倒だから。
- 会員として、共用 PC ではログアウトしたい。他人に入札されたくないから。
- 運営者として、利用停止したユーザーがログインし直して操作できないようにしたい。

## 機能要件

| # | 要件 |
|---|---|
| FR-1 | ログイン画面（ダイアログ）に「Google でログイン」ボタンを表示する。 |
| FR-2 | Google での認証に成功したら、サイトに戻ってログイン状態にする。認証前に開いていたページへ戻す（サイト内の URL に限る）。 |
| FR-3 | 初めての Google アカウントなら、`User` と `AuthIdentity` を作成する（会員登録）。2回目以降は既存の `User` でログインする。 |
| FR-4 | ユーザーの識別は Google の `sub`（アカウント固有 ID）で行う。**メールアドレスでは識別しない**（変わることがあるため）。 |
| FR-5 | 初回ログイン後にニックネーム（公開表示名）を設定してもらう。**Google の氏名や写真を、自動で公開プロフィールに出さない**（仮定。C2C サービスで本名が出るのを避けるため）。 |
| FR-6 | Google 側でメールアドレスが確認済み（`email_verified = true`）のアカウントだけを受け付ける。 |
| FR-7 | ログアウトすると、サーバー側のセッションを無効化し、ログイン前の状態に戻す。 |
| FR-8 | 利用停止中のユーザーは、Google 認証に成功してもログインさせず、理由を表示する。 |
| FR-9 | ユーザーがキャンセルした場合や認証に失敗した場合は、エラー内容を日本語で表示し、再試行できるようにする。 |
| FR-10 | 入札・出品・ウォッチなど、ログインが必要な操作を未ログインで行おうとしたら、ログインに誘導する。 |

## 非機能要件

- **セキュリティ**（AGENTS.md 7章）
  - 認証処理は実績のあるライブラリを使い、トークン検証や暗号処理を自前で書かない。
  - Google のクライアントシークレットは環境変数／Secrets Manager で管理し、Git にコミットしない。
  - ID トークン・認可コード・セッション ID をログに出さない。
  - ログインの開始とコールバックにレート制限を設ける。
- **プライバシー**：Google から受け取る情報は `sub`・メールアドレス・確認済みフラグに絞り、必要以上に保存しない（氏名・写真を保存するかは未決）。
- **UX**：モバイルでもキーボードでも操作できること。Google のボタンのデザインガイドラインに従うこと。

## 受け入れ条件

- [ ] 新しい Google アカウントでログインすると会員登録され、ニックネーム設定へ進む。
- [ ] 同じ Google アカウントで再ログインすると、同じユーザーとしてログインできる（重複してユーザーが作られない）。
- [ ] Google アカウントのメールアドレスが変わっても、同じユーザーとしてログインできる。
- [ ] ログアウト後は、ブラウザの戻るボタンを使っても会員専用の操作ができない。
- [ ] 利用停止ユーザーはログインできず、理由が表示される。
- [ ] 認証をキャンセルすると、エラーにならずにログイン前の画面へ戻り、再試行できる。
- [ ] 不正な `state` や改ざんされたトークンでのコールバックは拒否される。
